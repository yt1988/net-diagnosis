网络诊断原型

四项验证，决定第一版能依赖哪些能力。所有测量都在这个页面里进行，结果只在本机，点"导出"才会生成文件。

A · 隐藏的标签页能否保持每秒采样

开始后切到别的标签页（或最小化窗口）至少 10 分钟，再切回来看结果。Chrome 会在页面隐藏 5 分钟后加重节流，这里看两种计时方式在开着 / 不开 WebRTC 连接时的表现。

E · UDP：免费 STUN 探测

轮流向几个公共 STUN 服务器取公网地址，每次取地址就是一次 UDP 往返。请求丢了，浏览器会在 250 ms、750 ms、1750 ms 后重发，所以耗时会落在"往返"、"往返 + 250"、"往返 + 750"这几簇上，由此估算丢包。同时测到 Cloudflare 的 HTTPS 往返，和 Cloudflare 的 STUN 对比，看 UDP 是否比 TCP 差。

B · UDP 真丢包：WebRTC 经 TURN 绕回自己（已停用）

2026-11-06 实测：凭证吊销后、过了有效期，一小时后仍然能用，账单风险控制不住，所以停用。代码保留作参考。

两条 WebRTC 连接都强制走 Cloudflare TURN 中继，数据通道不可靠、不重传。往返时间约等于到 TURN 节点往返的两倍。每次运行单独申请一个凭证，只在这次测试期间有效，测完立即吊销；每人每天、全站每天的次数都有上限。

C · 网关探针（Chrome Local Network Access）

要在公网 HTTPS 页面上测才有意义：本机 localhost 打开时不会弹权限，也不涉及混合内容拦截。第一次请求时 Chrome 会询问是否允许访问本地网络，请自己决定是否允许。

D · 能否看出 HTTP/3 与 HTTP/2

对每个地址连续请求 8 次，读 Resource Timing 里的实际协议，看第几次起换成 HTTP/3，以及跨域时能否读到连接细节。
